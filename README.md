# turnstile_bridge

[Cloudflare Turnstile](https://developers.cloudflare.com/turnstile/) for Flutter apps, on Android, iOS, macOS, Windows, Linux and the web.

Turnstile only exists as a JavaScript widget, so on mobile and desktop the package runs it inside a WebView ([`flutter_inappwebview`](https://pub.dev/packages/flutter_inappwebview)). On the web there is no WebView at all: the widget is rendered straight into your page. Either way you work with the same Dart API.

What you get:

- `TurnstileWidget`, the visible widget. It resizes itself when Turnstile changes size (compact mode, interactive challenge, and so on).
- `TurnstileHeadless`, for invisible site keys. It runs the challenge off-screen and hands you a token.
- `TurnstileController` to reset, remove, re-render, execute, reload or destroy the widget, read its state and listen to its events.
- One event type per Turnstile callback (token, error, expiry, timeout, interaction, unsupported browser, resize), as a sealed class you can `switch` on.
- Cookies and local storage that survive app restarts, so returning users see fewer challenges.
- Error codes sorted into categories, with an `isRetryable` flag so you know whether a `reset()` is worth trying.

You still have to check every token on your server with the [siteverify API](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/). A token on its own proves nothing.

## Platform support

| Platform | Runs in | Status |
| --- | --- | --- |
| Android | Android WebView | tested |
| iOS | WKWebView | not tested yet |
| macOS | WKWebView | not tested yet |
| Windows | WebView2 | tested |
| Linux | WPE WebKit | experimental, not tested yet |
| Web | the page itself | tested |

"Tested" means the example app was run against the real Turnstile script with Cloudflare's test keys. iOS and macOS need a Mac I didn't have at hand. The Linux WebView plugin is still in its first beta, so expect rough edges there.

About the `flutter_inappwebview` dependency: this package requires 6.2.0, which is still a beta. The stable 6.1.5 doesn't build on Android with Android Gradle Plugin 9, the version used by current Flutter project templates. I'll switch to the stable 6.2.0 when it ships.

## Installation

```bash
flutter pub add turnstile_bridge
```

Then do the setup for each platform you target.

### Android

Release builds need the Internet permission in `android/app/src/main/AndroidManifest.xml` (debug builds already have it):

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

`minSdkVersion` must be 19 or higher, which the Flutter default already is.

### iOS

Nothing to do.

### macOS

The app sandbox blocks outgoing connections by default. Add this to both `macos/Runner/DebugProfile.entitlements` and `macos/Runner/Release.entitlements`:

```xml
<key>com.apple.security.network.client</key>
<true/>
```

### Windows

To build, you need the [NuGet CLI](https://learn.microsoft.com/nuget/install-nuget-client-tools) on your `PATH`, for example via `winget install Microsoft.NuGet`. The Windows WebView plugin uses it to download WebView2 and a couple of other native libraries. Without it the build stops with `NUGET-NOTFOUND`.

To run, users need the [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/). Windows 11 and an up to date Windows 10 already have it. For older machines, ship the Evergreen installer with your app.

### Linux

You need WPE WebKit. The system requirements are listed in [`flutter_inappwebview_linux`](https://pub.dev/packages/flutter_inappwebview_linux).

### Web

Add your site's domain to the allowed hostnames of your Turnstile widget in the Cloudflare dashboard. If your site sends a Content Security Policy, `script-src` and `frame-src` have to allow `https://challenges.cloudflare.com`.

## The `baseUrl` parameter

Turnstile checks the hostname of the page that hosts it. On mobile and desktop that page is generated by the package, and `baseUrl` decides which origin it gets. So:

1. In the Cloudflare dashboard, add a hostname to your widget, say `example.com`.
2. Pass `baseUrl: Uri.parse('https://example.com')`.

Nothing is ever downloaded from that URL. It only sets the origin of the page. If the hostname isn't on the list, Turnstile fails with error `110200`.

On the web `baseUrl` is ignored, because the widget runs on your real site.

While developing, Cloudflare's [test site keys](https://developers.cloudflare.com/turnstile/troubleshooting/testing/) save you from all of this. They accept any hostname:

| Site key | Behaviour |
| --- | --- |
| `1x00000000000000000000AA` | always passes, visible |
| `2x00000000000000000000AB` | always fails, visible |
| `1x00000000000000000000BB` | always passes, invisible |
| `2x00000000000000000000BB` | always fails, invisible |
| `3x00000000000000000000FF` | forces an interactive challenge |

## Usage

```dart
import 'package:turnstile_bridge/turnstile_bridge.dart';

TurnstileWidget(
  baseUrl: Uri.parse('https://example.com'),
  options: const TurnstileOptions(
    siteKey: '1x00000000000000000000AA',
    action: 'login',
  ),
  onTokenReceived: (token) => authApi.login(captchaToken: token),
  onError: (error) => debugPrint('Turnstile failed: $error'),
  onExpired: () => debugPrint('Token expired'),
);
```

### With a controller

```dart
final controller = TurnstileController();

TurnstileWidget(
  controller: controller,
  baseUrl: Uri.parse('https://example.com'),
  options: const TurnstileOptions(siteKey: '...'),
);

// The controller is a ChangeNotifier.
ListenableBuilder(
  listenable: controller,
  builder: (context, _) => FilledButton(
    onPressed: controller.hasToken ? submit : null,
    child: const Text('Sign in'),
  ),
);

// Or just wait for the next token.
final token = await controller.waitForToken(timeout: const Duration(minutes: 1));

await controller.reset();    // new challenge in the same WebView
await controller.remove();   // take the widget off the page, keep the WebView
await controller.render();   // put it back after remove()
await controller.execute();  // start the challenge when execution is "execute"
await controller.reload();   // reload the whole page
await controller.destroy();  // free the WebView right away
controller.recreate();       // build a new one after destroy()

// If you created the controller, dispose it.
controller.dispose();
```

What you can read from it:

| Member | Meaning |
| --- | --- |
| `status` | `idle`, `loading`, `ready`, `interactive`, `verified`, `expired`, `timedOut`, `failed`, `unsupported`, `destroyed` or `disposed` |
| `token`, `hasToken` | the last valid token |
| `lastError` | the last `TurnstileError` |
| `events` | a broadcast `Stream<TurnstileEvent>` |
| `isAttached` | whether a widget is currently connected |

### Events

```dart
controller.events.listen((event) {
  switch (event) {
    case TurnstileTokenReceived(:final token):
      send(token);
    case TurnstileFailed(:final error) when error.isRetryable:
      controller.reset();
    case TurnstileFailed(:final error):
      showFatal(error);
    case TurnstileExpired():
    case TurnstileTimedOut():
      controller.reset();
    case TurnstileInteractionRequired():
      scrollToWidget();
    case TurnstileLoaded():
    case TurnstileInteractionCompleted():
    case TurnstileUnsupported():
    case TurnstileResized():
      break;
  }
});
```

### Invisible keys

With an invisible site key there is nothing to show, so `TurnstileHeadless` runs the challenge off-screen:

```dart
final turnstile = TurnstileHeadless(
  baseUrl: Uri.parse('https://example.com'),
  options: const TurnstileOptions(siteKey: '1x00000000000000000000BB'),
);
try {
  final token = await turnstile.getToken(); // a new token on every call
  await api.submit(token);
} on TurnstileException catch (e) {
  // If e.error.code is TurnstileError.interactionRequiredCode, Cloudflare
  // wants the user to click something. Show a TurnstileWidget instead.
} finally {
  await turnstile.dispose();
}
```

## Freeing the WebView

The WebView, its JavaScript handler and the streams are released when `TurnstileWidget` leaves the widget tree. If the widget created its own controller, it disposes it too.

You can also let go of it earlier. `controller.destroy()` removes the widget, unloads the page and drops the platform view. After that the widget draws nothing until you call `controller.recreate()`. On a one-time form (sign up, password reset), calling `destroy()` once you have the token is a cheap way to get the memory back.

Controllers you create yourself need a `dispose()`. `TurnstileHeadless` needs one as well, ideally in a `finally` block.

## Cookies and storage

Clearance only sticks if cookies and storage survive, so `TurnstileWebViewConfig` keeps them. JavaScript, DOM storage, databases and the cache are on, incognito mode is off, and third-party cookies are allowed on Android because the Turnstile iframe comes from another origin. On iOS the shared cookie store is used.

To wipe everything, on logout for instance:

```dart
await const InAppWebViewTurnstileStorage().clear();
```

Careful: this clears cookies and website data for every WebView in your app, not only Turnstile's.

## Errors

A `TurnstileError` has the raw Turnstile `code`, a `category` and `isRetryable`.

| Category | Typical codes | Retry? | Usually means |
| --- | --- | --- | --- |
| `invalidConfiguration` | 110100, 110110, 110200, 110420, 110430, 400xxx | no | wrong site key, hostname not allowed (check `baseUrl`), bad `action` or `cData` |
| `unsupportedEnvironment` | 110500, 110510 | no | WebView not supported, or the user agent was changed |
| `initialization` | 100xxx, 105xxx, 200010 | no | Turnstile couldn't start |
| `clockSkew` | 200100 | no | the device clock is off |
| `challengeTimeout` | 11060x, 11062x | yes | the challenge or the interaction timed out |
| `challengeFailed` | 600xxx | yes | the challenge failed, possibly a bot |
| `clientExecution` | 102xxx to 106xxx, 120xxx, 300xxx | yes | generic client-side error |
| `network` | `script_load_failed`, `page_load_failed`, `load_timeout` | yes | no connection, or the Cloudflare domain is blocked |
| `bridge` | `not_attached`, `disposed`, `interaction_required`, ... | no | the package was used the wrong way |

If you disagree with this mapping, pass your own `TurnstileErrorClassifier` to `JsonTurnstileMessageDecoder`.

## Checking the token on your server

Send the token to your backend and call siteverify with your secret key. The secret key never goes in the app.

```bash
curl -X POST https://challenges.cloudflare.com/turnstile/v0/siteverify \
  -d secret=YOUR_SECRET_KEY \
  -d response=TOKEN_FROM_THE_APP
```

A token can be used once, and it expires after 300 seconds.

## Replacing parts

Each piece below is an interface with a default implementation, so you can swap one out without forking:

| Interface | Default | Role |
| --- | --- | --- |
| `TurnstileEngine` | `InAppWebViewTurnstileEngine` on native, a JS interop engine on the web | hosts Turnstile on a family of platforms |
| `TurnstileDocumentBuilder` | `TurnstileHtmlDocumentBuilder` | writes the HTML page (script URL, styling) |
| `TurnstileNavigationPolicy` | `DefaultTurnstileNavigationPolicy` | decides which navigations stay in the WebView |
| `TurnstileLinkHandler` | `SystemBrowserLinkHandler` | opens the privacy and terms links |
| `TurnstileMessageDecoder` | `JsonTurnstileMessageDecoder` | turns JS messages into events |
| `TurnstileSession` | `InAppWebViewTurnstileSession` | the connection the controller talks to (handy to fake in tests) |
| `TurnstileStorage` | `InAppWebViewTurnstileStorage` | clears persisted data |

## How the code is organised

| Folder in `lib/src/` | Contents |
| --- | --- |
| `core/` | options, events, errors, status (plain Dart) |
| `bridge/` | `TurnstileSession`, commands, message decoder |
| `engine/` | `TurnstileEngine` and the per-platform choice made at compile time |
| `html/` | the HTML/JS page used by the WebView engine |
| `controller/` | `TurnstileController` |
| `webview/` | `flutter_inappwebview` engine (Android, iOS, macOS, Windows, Linux) |
| `web/` | web engine (JS interop, no WebView) |
| `widgets/` | `TurnstileWidget` |
| `headless/` | `TurnstileHeadless` |

The controller only knows about `TurnstileSession`, never about a WebView, which is why it can be tested with a fake session. The widget and the headless runner only know about `TurnstileEngine`. Adding a platform means writing an engine, and neither of them has to change. Both engines send the same JSON messages, read by the same decoder. The names shared between Dart and JavaScript (handler, global object, container id) are defined once, in `TurnstileJsApi`.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| Error `110200` | The `baseUrl` host isn't in the widget's allowed hostnames. |
| Error `110510` | Don't set a custom `userAgent`. |
| `load_timeout` or `script_load_failed` | Check that `challenges.cloudflare.com` is reachable: VPN, firewall, or an Android release build without the `INTERNET` permission. |
| The widget ignores taps inside a scroll view | Pass `gestureRecognizers: {Factory(() => EagerGestureRecognizer())}`. |
| Headless mode throws `interaction_required` | The key isn't invisible, or Cloudflare wants a click. Show a `TurnstileWidget`. |
| Web: `load_timeout` after opening the page in a background tab | Browsers pause Flutter's rendering in hidden tabs. The widget catches up once the tab is visible. `TurnstileController(loadTimeout: null)` turns the timeout off. |
| Web: nothing shows up, CSP errors in the console | Allow `https://challenges.cloudflare.com` in `script-src` and `frame-src`. |
| Windows: the widget stays blank | Install the WebView2 Runtime. |
| Windows build fails with `NUGET-NOTFOUND` | Install the NuGet CLI and check that `nuget.exe` is on the `PATH`. |
| Windows build fails with `Package 'nlohmann.json 3.12.0' is not found` | Some NuGet CLI versions can't resolve this dependency of the Windows WebView plugin. Download `nlohmann.json.3.12.0.nupkg` from nuget.org, extract it into `build/windows/x64/packages/nlohmann.json/`, keep the `.nupkg` next to it as `nlohmann.json.nupkg`, and build again. |
